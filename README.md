# Мягко — заявки на выездную химчистку мебели

Шаблон PWA-сайта для компании по химчистке мягкой мебели. Клиент выбирает мебель,
видит предварительную цену, добавляет фото и отправляет заявку. Владелец
согласует цену и время в кабинете, клиент видит изменения по приватной ссылке.

Один экземпляр = одна компания = одна база. Мультитенантности нет.

## Стек

- Next.js 16 (App Router, Turbopack), React 19, TypeScript
- Tailwind CSS 4 + CSS-переменные из `DESIGN.md`
- Motion для переходов
- PostgreSQL + Drizzle ORM, миграции в `drizzle/`
- Zod на границе API
- Vitest (формула, API-хендлеры, доступ), Playwright (сквозной сценарий)
- Локально без Docker: PGlite (Postgres в WASM); на сервере — обычный PostgreSQL

## Быстрый старт

Требуется Node.js 20.9+ (проверено на Node 26) и npm.

```bash
npm ci
cp .env.example .env     # Windows: copy .env.example .env
# заполните AUTH_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
npm run db:migrate
npm run db:seed
npm run dev
```

- Сайт: http://localhost:3000
- Кабинет: http://localhost:3000/admin
- Локальная база: `pglite://.data/dev` (файл в `.data/`, Docker не нужен)

`AUTH_SECRET` сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`.

После сида вход сразу ведёт в заявки. Принудительная смена пароля при первом
входе включается `ADMIN_MUST_CHANGE_PASSWORD=true` или CLI-сбросом
(`npm run admin:reset`).

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | `postgresql://…` для сервера или `pglite://.data/dev` локально |
| `NEXT_PUBLIC_SITE_URL` | Публичный адрес, HTTPS в продакшене |
| `AUTH_SECRET` | 32+ случайных байта; HMAC для rate limit |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Первый владелец для `db:seed` / первого старта |
| `ADMIN_MUST_CHANGE_PASSWORD` | `true` — требовать смену пароля после сида; по умолчанию `false` |
| `PHOTO_STORAGE` | `local` или `s3` |
| `PHOTO_STORAGE_DIR` | Папка фото для `local` (вне `public/`) |
| `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Приватный бакет для `s3` |

`.env` в репозиторий не попадает. Секретов в коде нет.

## Расчёт

Формула живёт в одном месте — `src/lib/calc/pricing.ts`, сервер вызывает её
сам и не доверяет сумме из браузера.

```
позиция = база × количество × (1 + грязь%) × (1 + вторая сторона%)
сумма   = Σ позиций
        → минимум за чистку (только по известным ценам)
        → выезд за город (фиксированно, на заказ)
        → округление вверх до 10 ₽ один раз в конце
```

- Проценты применяются последовательно: `3200 × 1.3 × 1.5 = 6240`.
- «Другое» — «По фото», в смешанном заказе известная сумма показывается отдельно.
- В заявке сохраняется снимок тарифов (`price_snapshot`) и разбивка; изменение
  прайса не меняет старые заявки.
- Деньги — целые рубли. Промежуточные строки округляются до рубля, итог — до шага
  округления.

Покрыто тестами: обычный заказ, количество, загрязнения, вторая сторона, минимум,
выезд, смешанный заказ, округление, пустой заказ, недопустимые флаги.

## Фото

- В корзине фото лежат в IndexedDB (не localStorage) и переживают перезагрузку.
- На сервер уходят одним пакетом в момент отправки — сирот при брошенной корзине нет.
- Клиент сжимает до 1600px перед отправкой, сервер заново проверяет тип по сигнатуре
  (sharp), ограничивает 10 МБ на файл, перекодирует в WebP, вырезает EXIF.
- Хранилище приватное, ключи — UUID, отдача через `/api/photos/[id]` с проверкой
  права (токен заявки или сессия владельца). Неверный id и чужой токен — 404.
- Лимиты: 3 фото на позицию, 15 на заказ, 60 МБ на заказ.

## Безопасность

- Сессия владельца — httpOnly cookie, argon2id, rate limit на логин, смена пароля
  закрывает все старые сессии.
- Все `/admin` закрыты на сервере; API дополнительно проверяет сессию.
- Создание заявки и логин ограничены по частоте (скользящее окно в Postgres).
- Мутации проверяют `Origin`.
- Приватные страницы и API: `no-store`, `X-Robots-Tag: noindex`.
- В логи не попадают имя, телефон, адрес и содержимое заметок.

## Деплой

### Vercel + Neon

1. Создайте Postgres в Neon, возьмите `DATABASE_URL` с `sslmode=require`.
2. Задайте переменные из таблицы выше. Фото — `PHOTO_STORAGE=s3` (R2 или S3,
   бакет приватный): файловая система Vercel не сохраняет файлы.
3. Примените миграции и сид из локального окружения с прод-`DATABASE_URL`:
   `npm run db:migrate && npm run db:seed`.
4. `next build` на Vercel; `RUN_MIGRATIONS` не задавайте.

Ограничение Vercel: тело запроса около 4.5 МБ. Клиент сжимает фото, поэтому
15 снимков обычно укладываются; для больших объёмов используйте VPS.

### VPS: Docker Compose + Caddy

1. Скопируйте проект на сервер, создайте `.env` рядом с `docker-compose.yml`:
   `POSTGRES_PASSWORD`, `AUTH_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `DOMAIN`.
2. `docker compose up -d --build`.
3. При старте контейнер применяет миграции и идемпотентно создаёт компанию,
   тарифы и владельца (`RUN_MIGRATIONS=1`, `SEED_ON_START=1`).
4. Caddy сам получит HTTPS для `DOMAIN`. Тома: база, фото, сертификаты.

Сброс пароля владельца выполняется из копии проекта с прод-`DATABASE_URL`
(почтового восстановления нет):

```bash
DATABASE_URL="postgresql://…" npm run admin:reset -- --email=owner@example.ru
```

## Проверки

```bash
npm run typecheck
npm run lint
npm run test
npm run test:e2e
npm run build
```

E2E поднимает отдельную базу `.data/e2e` и проверяет:
сборку заказа, фото, перезагрузку черновика, удаление с возвратом, отправку,
кабинет, список с фактическими доплатами («грязь» / «без доплат»), согласование,
автообновление приватной ссылки, дубль по idempotency key, три состояния минимума,
закрытые маршруты, 360/390/768/1280, тёмную тему и подписи времени.

## Что не входит в шаблон

Новые услуги, онлайн-оплата, календарь мастеров, роли и права, CRM, SMS/почтовые
уведомления, интеграции, новые экраны, смена логотипа и полной палитры дизайнером.
Это оценивается отдельно.

## Известные ограничения

- Деплой на Vercel/Neon и сборка Docker-образа не проверялись в этом окружении:
  нет Docker и доступов к Vercel. Локально проверены `next build`, `next start`
  и весь E2E.
- На Vercel лимит тела запроса ~4.5 МБ; фото сжимаются на клиенте, но очень
  тяжёлый заказ лучше принимать на VPS.
- PGlite — только для разработки и тестов. На сервере обязателен PostgreSQL.
- Иконки PWA и OG-картинка сгенерированы из глифа-заглушки: нужны исходники
  клиента (`scripts/generate-assets.ts`).
- Токены `--ink-3` из `DESIGN.md` (`#9A9388` на светлой бумаге) дают контраст
  ниже 4.5:1. Оставлены как в дизайн-системе; для важных подписей используется
  `--ink-2`.
- Восстановление пароля по почте не входит в объём: только CLI-сброс.
