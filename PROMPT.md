## Продукт

PWA-сайт. Клиент открывает ссылку из профиля мастера, выбирает мебель, видит предварительную цену, отправляет заявку с фото и адресом. Заявка попадает в кабинет владельца. Владелец согласует цену и время, клиент видит изменения по своей приватной ссылке.

Задача бизнеса: убрать ручной расчёт «сколько стоит диван» из переписки.

Один экземпляр приложения = одна компания = своя база. Мультитенантность не нужна. Сайт после передачи должен работать без тебя, без ассистента, без платного LLM.

## Расчёт стоимости

Прайс хранится в базе и меняется в кабинете. Значения ниже — демо для Новосибирска, они должны быть редактируемыми, а не зашитыми в код.

- Диван: 2 места 2 500 ₽, 3 места 3 200 ₽, угловой 4 200 ₽.
- Кресло: обычное 1 200 ₽, реклайнер 1 800 ₽.
- Матрас: односпальный 1 500 ₽, двуспальный 2 400 ₽; вторая сторона +50%.
- Стул: сиденье 500 ₽, сиденье со спинкой 700 ₽.
- Минимальный заказ 2 500 ₽ (относится к чистке, выезд считается отдельно).
- Сильные загрязнения: +30%.
- Выезд за город: +500 ₽ фиксированно.
- Округление: до 10 ₽ вверх, применяется один раз в конце.

**Порядок применения:** базовая цена варианта → × количество → процент за сильные загрязнения → процент за вторую сторону матраса → сложение всех позиций → применение минимума → доплата за выезд → округление.

Правила, которые нельзя нарушить:
1. **Сервер пересчитывает всё сам.** Сумме из браузера не доверяет: принимает только состав и параметры.
2. В заявке сохраняется **снимок тарифов** на момент отправки. Изменение прайса не меняет старые заявки.
3. Позиция «Другое» показывается как «По фото», а не как 0 ₽. В смешанном заказе отдельно показывается известная сумма и предметы с ручной оценкой.
4. Формула покрыта юнит-тестами: обычный заказ, количество, загрязнения, вторая сторона, минимум, выезд, смешанный заказ, округление.

## Клиентский путь

**1. Первый экран.** Название, город, короткое объяснение, карточки: Диван, Кресло, Матрас, Стул, Другое. У каждой — цена «от» и подпись. Выбор варианта — пилюли под карточкой (2 места / 3 места / угловой и т.д.). Внизу закреплённая панель с выбранным и кнопкой «В корзину».

**2. Корзина.** Список позиций, количество, удаление с возможностью вернуть (тост 5 секунд). Одинаковые позиции объединяются, разные конфигурации — отдельными строками. Пустое состояние. Итог с расшифровкой.

Фото прикрепляются **к каждой позиции прямо в корзине**, а не отдельным шагом в конце: маленькая кнопка «+ Фото» у позиции, превью 56–72px, удаление. Для «Другое» фото обязательно — без него заявка не уходит. Для остальных необязательно, но под итогом честная строка: «Фото 1 из 2. У кресла фото нет — цена по нему останется предварительной».

**Технически важно:** файлы не загружаются на сервер из корзины (иначе останутся сироты без заявки). Фото хранятся локально в браузере (`IndexedDB`, не `localStorage`), переживают перезагрузку, а на сервер уходят одним пакетом в момент отправки заявки. После успешной отправки локальный черновик очищается.

**3. Оформление.** Имя, телефон, адрес, выезд за город, желаемые дата и время, комментарий, согласие на обработку данных. Фото здесь не запрашиваются заново — только сводка: превью, «добавить ещё», сколько позиций без фото. Дата и время необязательны; время без даты не принимается.

**4. Отправка.** Повторная отправка при сетевом сбое не создаёт дубль (idempotency key). Успех показывается только после записи в базу. Открывается приватная ссылка с составом, статусом, ценой и временем; ссылку можно скопировать.

**5. Приватная ссылка.** Доступ по непредсказуемому токену, не по номеру заявки. Перебор номеров невозможен. Страница обновляется, когда владелец меняет статус, цену или время.

Черновик корзины и формы (позиции, контакты, выбранные фото) переживает перезагрузку: состав — `localStorage`, фото — `IndexedDB`. Очистка после успешной отправки.

## Кабинет

Авторизация владельца: логин/пароль, сессия в httpOnly cookie, защита от подбора, смена пароля с инвалидацией старых сессий. Все маршруты `/admin` закрыты на сервере, не только в UI.

Разделы:
- **Заявки** — список с поиском, фильтрами по статусу, обновлением. Карточка: контакт, фото, состав, пожелания, предварительный расчёт, история. Действия: итоговая цена, согласованное время, смена статуса, приватная заметка, удаление с подтверждением.
- **Тарифы** — все цены и доплаты из раздела «Расчёт».
- **Компания** — название, контакты, город, территория, акцентный цвет.
- **Доступ** — смена пароля, выход.

Статусы: `новая`, `согласована`, `завершена`, `отменена`. Переход в «согласована» требует заполненных цены и времени.

Заметки владельца и фото не отдаются через публичные API.

## Безопасность и данные

- Секреты только в переменных окружения, `.env.example` в репозитории без значений.
- Фото: проверка реального типа файла на сервере (не по расширению и не по `Content-Type`), лимит размера, сжатие, хранение вне публичной папки, отдача через защищённый роут с проверкой права. Предсказуемый URL фото не должен открываться.
- Ограничение частоты на создание заявки и на логин.
- Проверка origin для мутаций.
- Никаких клиентских данных в логах.
