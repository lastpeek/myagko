# Конструктор расчёта — design doc

Статус: предложение. Код не начат. Цель — владелец настраивает нишу, услуги, параметры и правила без разработчика.

## 1. Модель данных

| Сущность | Где | Поля | Пример |
|---|---|---|---|
| Категория | текущая `services` | `id`, `label`, `hint`, `icon`, `sort_order`, `is_active` | «Химчистка мебели» |
| Услуга | новая `catalog_services` | `id`, `category_id`, `label`, `hint`, `icon`, `sort_order`, `is_active` | «Диван» |
| Вариант | текущая `tariff_items` | `id`, `service_id`, `variant_label`, `unit`, `parameter_label`, `base_price`, `min_value`, `max_value`, `step`, `is_manual`, `requires_photo`, `sort_order`, `is_active` | «2 места», шт, 3 200 ₽ |
| Опция | текущая `price_options` | `id`, `label`, `kind`, `value`, `scope`, `sort_order`, `is_active` | «Грязь +30%», «Углы 200 ₽/шт», «Доставка 500 ₽/заказ» |
| Связь | текущая `tariff_item_options` | `variant_id`, `option_id` | «Вторая сторона» только у матраса |
| Правила | текущая `tariff_settings` | `min_order`, `rounding_step`, `out_of_town_fee` и лимиты фото | минимум 2 500 ₽, округление 10 ₽ |

Ключевое ограничение: **у варианта ровно один ценовой параметр**. `unit` — подпись (`шт`, `м²`, `м.п.`, `услуга`), в формуле участвует только число. Значение параметра — `numeric(10,2)`, у варианта есть `min_value`, `max_value`, `step` (`0.1` для м², `1` для штук).

Опции: `percent` — процент от текущей суммы позиции; `fixed` — рублей за штуку опции; `fixed_order` — рублей за заказ, один раз. У выбранной `fixed`-опции есть **собственное количество** (по умолчанию 1; клиент может указать 4 угла). Оно не связано с площадью или количеством параметра. Проценты и `fixed` привязываются к варианту; `fixed_order` — глобальная опция заказа, к варианту не привязывается.

## 2. Формула и снимок

Порядок жёсткий, владелец его не меняет:

1. Значение параметра — `numeric(10,2)`. Сервер проверяет `min/max` и кратность `step`; иначе 400.
2. База строки: `parameter_value × base_price`.
3. Опции строки по `sort_order`:
   - `percent` — последовательно от текущей суммы позиции;
   - `fixed` — `value × option_quantity`, где `option_quantity` — количество этой опции;
   - `fixed_order` — не в строку, а в заказ.
4. `itemsSubtotal = Σ строк`.
5. Минимум — только если есть хотя бы одна строка с известной ценой: `max(0, min_order − itemsSubtotal)`.
6. `fixed_order` — по одному разу на уникальную опцию заказа.
7. Выезд за город — системное правило `out_of_town_fee`, после минимума.
8. `total = ceil((itemsSubtotal + minimumApplied + orderOptionsTotal + outOfTownFee) / rounding_step) × rounding_step` — один раз в конце.

Цены и итог — целые рубли. Чтобы дробные м² не теряли точность, промежуточные суммы считаются в копейках; это точность хранения, а не отдельное правило округления. Финальное округление до шага — одно, в конце.

Заказ только из «По фото»: минимум не применяется, `total = outOfTownFee` или `0`, интерфейс показывает «по фото». Смешанный заказ: известная сумма считается, позиции «По фото» оцениваются вручную.

Снимок заявки:

- `line`: `serviceId`, `serviceLabel`, `variantId`, `variantLabel`, `unit`, `parameterValue`, `pricePerUnit`, `baseTotal`, `options[{id,label,kind,value,quantity,amount}]`, `lineTotal`.
- `order`: `itemsSubtotal`, `minimumApplied`, `orderOptions[]`, `orderOptionsTotal`, `outOfTownFee`, `total`, `rules{minOrder,roundingStep}`.

Дополнительно `price_snapshot` хранит каталог на момент заявки: категории, услуги, варианты (`unit`, `parameter_label`, цена за единицу, min/max/step), опции (`kind`, `value`, `scope`, порядок) и связи вариант–опция. Старые заявки читаются по старой форме и не пересчитываются.

## 3. Текущая схема и миграция химчистки

Переиспользуем: `orders`, `order_items`, `order_photos`, `order_events`, `tariff_settings`, авторизацию, фото, галерею, Telegram. Текущую `services` трактуем как **категории** (в коде можно позже переименовать в `service_categories`, на формулу это не влияет).

Добавляем:

- `catalog_services` — услуги внутри категории.
- В `tariff_items`: `service_id`, `unit`, `parameter_label`, `min_value numeric(10,2)`, `max_value numeric(10,2)`, `step numeric(10,2)`. `base_price` остаётся ценой за единицу.
- В `price_options`: `scope` (`line` / `order`). `fixed_order` → `order`, остальные → `line`.
- В `order_items`: `quantity` и `line_total` — `numeric(10,2)`, плюс `unit`, `parameter_label`. Количество `fixed`-опции и её сумма хранятся в `options` JSON.

Миграция:

1. Создать `catalog_services`, заполнить уникальными парами `(category, label)` из `tariff_items`, ID детерминированные.
2. Добавить колонки в `tariff_items`, заполнить `service_id` по той же паре. Существующим вариантам: `unit='шт'`, `parameter_label='Количество'`, `min=1`, `max=99`, `step=1`.
3. Проставить `scope` опциям; старые связи `fixed_order` игнорировать, заказные опции в `tariff_item_options` не создавать.
4. «Другое» остаётся ручным вариантом без цены, с обязательным фото по настройке компании.
5. `orders` и `order_items` не переписывать: старые значения читаются как есть, новые поля nullable. Старые снимки и разбивка не пересчитываются.

Удаление справочников: категорию, услугу или вариант, на которые ссылаются заявки, удалять нельзя — только `is_active = false`. Удаление разрешено, если ссылок нет: у категории нет услуг, у услуги нет вариантов, у варианта нет `order_items.tariff_item_id`. Проверка живёт в API удаления; UI предлагает «Скрыть», если удаление запрещено.

Старые таблицы и колонки сохраняются до вывода нового кабинета; удаление — отдельным релизом после проверки. ID вариантов не переиспользуются, услуги и варианты архивируются, а не удаляются.

## 4. Границы модели

Разрешено только: `значение × цена за единицу` по строке, сумма строк, проценты последовательно, фикс за штуку опции, фикс за заказ, минимум, выезд, округление вверх.

Запрещено: свободные формулы и выражения, условия `if`, зависимость цены от двух параметров, матрицы «материал × размер», ступенчатые/объёмные скидки, налоги, скидки, промокоды, валюты, отрицательные цены, ручной ввод суммы клиентом. Если бизнес-правило не раскладывается в эту цепочку — это отдельная разработка, а не новая настройка.

## 5. Что настройка, а что код

Владелец настраивает: категории, услуги и варианты (создание, названия, подсказки, иконка из набора, порядок, архив); параметр варианта (подпись, единица, цена за единицу, min/max/step); ручной вариант и требование фото; опции (`percent`, `fixed`, `fixed_order`), их значения, порядок и привязку к вариантам; минимум, шаг округления, выезд за город; компанию, контакты и акцентный цвет.

В коде остаются: формула и порядок применения, виды опций, набор единиц и иконок, округление и масштабирование, валидация, формат снимка, совместимость со старыми заявками, статусы и история заявок, авторизация и безопасность, фото-пайплайн, дизайн-система и структура экранов, PWA/SEO, API и схема БД.

Клиент **не может** менять: формулу и условия, добавлять второй параметр, ступенчатые цены, налоги/скидки/промокоды/оплату, валюту, режим и порядок округления, область действия минимума, новые виды опций, новые экраны и поля, роли и права, статусы заявок, логотип, типографику и полную палитру (акцентный цвет — можно), обработку и лимиты фото, авторизацию, ID и старые заявки. Клиент может выбрать количество `fixed`-опции, но не её цену и не правило расчёта.

## 6. Риски и что делать

| Риск | Поведение |
|---|---|
| Цена зависит от двух параметров (площадь + периметр) | Модель не поддерживает. Разбить на две позиции/варианта или считать вручную; иначе — разработка. |
| Цена зависит от условия (этаж, материал, срочность) | Сделать отдельные варианты или аддитивные опции. Мультипликативные условия — только код. |
| Ступенчатые/объёмные цены | Не поддерживаются. Средняя цена, отдельные позиции или разработка. |
| Минимум должен включать выезд/фикс заказа | Сейчас минимум только по строкам. Если нужно иначе — менять формулу в коде, не настройкой. |
| Владелец складывает проценты (30% + 50% = 80%) | Проценты применяются последовательно (1,3 × 1,5). Показывать формулу в кабинете; для суммы использовать одну опцию. |
| Дробные м² и округление до нуля | Значение `numeric(10,2)`, min/max/step, промежуточные копейки, финальное округление одно; тесты на 0,1 и 0,01. |
| `fixed`-опция умножается на площадь | Количество опции своё (`option_quantity`), по умолчанию 1; тест «4 угла при 20 м² = 4 × цена». |
| Удаление услуги/варианта/опции | Архив при ссылках из заявок; удаление только без ссылок; ID не переиспользовать; снимки не трогать. |
| Грязные данные при миграции (дубли, null, неверные флаги) | Прогон на копии, отчёт аномалий, ручные варианты как fallback; старые заявки не пересчитывать. |
| Выезд за город vs фикс заказа | Выезд — системное правило по адресу; остальные фиксы — `fixed_order`. Не смешивать в одной опции. |
| Свободный текст единицы | Единица — только подпись, в формуле не участвует; ограничить длину и подсказать пресеты. |
| Огромные значения/переполнение | Верхние границы min/max, проверка на сервере, промежуточные копейки в integer. |
| Старые заявки после смены каталога | Читать сохранённый снимок, не текущий каталог; новые поля nullable; тест на неизменность JSON. |

## Решения, которые нужно подтвердить

1. Один ценовой параметр на вариант — сознательное ограничение v1.
2. Выезд за город остаётся системным правилом, а не опцией каталога.
3. Текущую `services` считаем категориями; новую таблицу услуг называем `catalog_services`.
